Архитектура доменов определяет, насколько быстро и надёжно посетители попадают к статическим сервисам и WebGL-приложениям из любой точки мира, сохраняя изоляцию каждого репозитория.

## Основные типы записей в продакшене

| Запись | Пример цели | Назначение |
|---|---|---|
| **NS** | Авторитативные NS Cloudflare | Делегирует управление DNS-зоной основного домена |
| **A / AAAA** | Anycast IP GitHub Pages | Привязывает корневой `idominiqe.com` через CNAME flattening |
| **CNAME** | `idominiqe.github.io` | Независимо маршрутизирует `portfolio`, `smartcity-v3`, `blaze`, `v-2` |
| **TXT** | Верификация и SPF / DMARC | Подтверждение прав на домен и защита от спуфинга |
| **CAA** | Центры сертификации | Ограничивает список УЦ, которым разрешён выпуск SSL/TLS |

## Архитектура изоляции поддоменов

Каждый поддомен экосистемы **iDominiqe** указывает на свой отдельный репозиторий:

1. `idominiqe.com` → `iDominiqe/idomi` (основной хаб на Astro Starlight)
2. `portfolio.idominiqe.com` → `iDominiqe/portfolio` (одноэкранное портфолио VisionOS)
3. `smartcity-v3.idominiqe.com` → `iDominiqe/smartcity-v3` (3D PBR командный центр)
4. `v-2.idominiqe.com` → `iDominiqe/v-2` (архив Liquid Glass Bento)

Поскольку каждый репозиторий хранит собственный файл `CNAME` и артефакты `gh-pages` или `main`, обновление одного проекта никогда не ломает соседние сервисы.

## Чек-лист DNSSEC и распространения

- Включайте **DNSSEC** и у регистратора, и в DNS-зоне для защиты от отравления кеша.
- Держите короткий TTL (`Auto` / `60–300s`) при миграциях, а затем полагайтесь на Anycast.
- Проверяйте живое разрешение имён через `nslookup -type=CNAME <host>` и `curl -I https://<host>/` после любых правок DNS.
